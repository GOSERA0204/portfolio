# 박소정 | WON ATTACK

서비스가 사용하는 데이터의 정확성과 처리 과정의 신뢰성을 고려하며 백엔드 개발 역량을 쌓고 있습니다. 이번 프로젝트에서는 AI가 추출한 투자 주장의 검색 조건을 정리하고, 공식 공시 검색부터 사실 검증까지 연결되는 분석 흐름을 개선했습니다.

## 1. 해결하려는 문제

투자 영상의 정보를 바탕으로 매수나 추가 매수를 검토하는 개인 투자자는 영상 속 재무 수치의 출처를 확인하기 위해 DART 공시나 기업 IR 자료를 직접 검색하고, 기업명과 실적 발표 기간을 비교해야 합니다. 영상에는 확정된 실적과 미래 전망이 섞여 있으며, 투자자의 보유 비중에 따라 고려해야 할 위험도 달라집니다.

팀은 영상 URL을 전달하면 주요 주장을 추출하고, 공식 공시와 대조한 결과를 출처와 함께 제공하는 서비스를 구현했습니다. 해당 투자자의 가상 포트폴리오를 활용한 위험 설명도 리포트에 포함했습니다.

| 사용자 문제 | 구현 기능 |
| --- | --- |
| 공식 공시 근거를 직접 찾기 어려움 | 기업·기간 필터와 벡터 유사도 기반 근거 검색 |
| 실적과 전망이 섞여 판단하기 어려움 | 주장 추출 및 유형 분류, 주장별 사실 검증 |
| 근거가 무엇인지 확인하기 어려움 | 공시 제목·기간·원문 링크를 포함한 리포트 |
| 투자 상황에 따라 위험이 달라짐 | 보유 비중·투자 성향에 따른 위험 설명 |

## 4. 주요 개인 기여

### 4.1 OpenAI·Ollama 임베딩 전환 및 공시 검색 연동

**문제.** 기존 `EmbeddingService`는 OpenAI 클라이언트를 통해 임베딩을 생성했습니다. 로컬 Ollama 모델을 함께 사용할 경우 임베딩 모델마다 벡터의 차원이나 표현 공간이 달라질 수 있으며, 적재할 때 사용한 모델과 검색할 때 사용하는 모델의 일치가 필요했습니다.

**구현.** `EmbeddingSettings`로 제공자·모델·컬렉션을 관리하고 `EmbeddingService`에서 OpenAI 또는 Ollama를 호출하도록 변경했습니다. `ChromaClient`도 선택된 컬렉션을 사용하도록 수정했습니다. Ollama 응답은 숫자이며 유한한 벡터 원소인지 검사하고, 빈 벡터인 경우 예외를 발생시킵니다.

```java
this.collection = collection
        + (this.provider.equals("ollama") ? "_ollama" : "");
```

| 제공자 | 임베딩 모델 | 기본 컬렉션 |
| --- | --- | --- |
| OpenAI | `text-embedding-3-small` | `disclosures` |
| Ollama | 설정값 (통합 테스트: `bge-m3:latest`) | `disclosures_ollama` |

**결과.** 설정을 바꾸면 검색 시 사용할 임베딩 제공자와 컬렉션을 함께 전환할 수 있게 되었습니다. 기존 OpenAI 호출도 유지했습니다. 모델 변경 시 공시 데이터 역시 해당 모델로 다시 적재해야 합니다.

**작업 근거.** [e382d47 — 임베딩 전환 및 검색 테스트](https://github.com/won-attack/won-attack/commit/e382d472d361243bc4285c8911b8948000040b27) (`EmbeddingSettings`, `EmbeddingService`, `ChromaClient`, `EmbeddingProviderTest`, `OllamaRagIntegrationTest`)

### 4.2 투자 주장 추출 및 유형 분류 개선

**문제.** 기존 프롬프트는 2~3개의 투자 주장을 추출하도록 요청했고, Mock 분류 로직은 `확정`이라는 표현만으로도 예측에 해당한다고 판단할 수 있었습니다. 예측으로 분류된 주장은 공시 검색과 사실 검증을 생략하기 때문에 분류 결과가 이후 처리에 영향을 미칩니다.

**구현.** 최대 3개의 핵심 주장을 추출하되 광고·인사말·반복 발언을 제외하고, 원문의 수치·단위·부정·불확실성·발언 주체를 보존하도록 프롬프트를 수정했습니다. 공백·문장 끝 기호·대소문자를 정리한 문자열을 기준으로 중복 주장도 제거했습니다. 주장 유형이 정해진 단일 값인지 검증하고, 검증할 주장이 없으면 빈 목록을 반환하도록 개선했습니다.

| 유형 | 판단 대상 |
| --- | --- |
| `FINANCIAL` | 기업이 발표한 매출·영업이익 등 재무 수치 |
| `DISCLOSURE` | 기업 공시, 사업 이벤트, 발표 일정 |
| `PREDICTION` | 미래 주가 전망 및 아직 발표되지 않은 실적 추정 |

**결과.** 중복 발언이 최대 추출 건수를 차지하는 문제를 줄이는 로직을 추가했고, 검증할 주장이 없는 영상도 정상적인 결과로 처리할 수 있게 되었습니다. 잘못된 유형의 JSON은 예외로 처리해 후속 검증 단계에 전달되는 데이터를 제한했습니다.

**작업 근거.** [86d812a — 대본 연동 및 주장 추출 개선](https://github.com/won-attack/won-attack/commit/86d812a72a3ba5772c55af4fdf64af77bfd0cfaa), [48adb90 — 분류 규칙 및 응답 검증 강화](https://github.com/won-attack/won-attack/commit/48adb90ed11280dcd40d79c93c07a62a3d1603af) (`ClaimService`, `AnalyzeService`, `ClaimServiceTest`)

### 4.3 영상 게시일 기준 기간 정규화

**문제.** 투자 영상의 ‘지난해 4분기’ 같은 표현을 분석하는 현재 시점 기준으로 해석하면 실제 영상이 지칭한 실적 기간과 다른 공시가 검색될 수 있습니다. 공시 검색의 기간 조건에 직접 영향을 주는 문제였습니다.

**구현.** `DataService`에서 영상 게시일을 읽고 `AnalyzeService`가 `ClaimService`에 전달하도록 수정했습니다. 프롬프트에 게시일을 명시하고, 정규표현식으로 상대적 기간 표현을 직접 변환하는 로직을 추가했습니다. 게시일이 있는 경우 대본과 게시일의 연도 정보로 뒷받침되지 않는 추출 연도는 검색 조건에서 제외합니다.

예를 들어 게시일이 2026년 1월 8일인 영상에서 다음과 같이 변환합니다.

| 원문 표현 | 정규화 결과 |
| --- | --- |
| 지난해 4분기 | `2025-Q4` |
| 지난해 연간 | `2025-FY` |
| 올해 1분기 | `2026-Q1` |

**결과.** 영상의 시간적 맥락을 기준으로 기업 공시를 검색할 수 있도록 입력 데이터를 정리했습니다. 이 결과는 `ChromaRagService`가 사용하는 기간 필터에 연결됩니다.

**작업 근거.** [48adb90 — 게시일 기반 정규화 및 테스트](https://github.com/won-attack/won-attack/commit/48adb90ed11280dcd40d79c93c07a62a3d1603af) (`DataService`, `AnalyzeService`, `ClaimService`, `ClaimServiceTest`)

### 4.4 실제 AI·ChromaDB를 사용한 분석 통합 테스트

공시 검색부터 사실 검증까지 연결되는 과정에서 각 단계의 입력과 출력이 다음 단계의 요구 조건을 충족하는지 확인할 수 있도록 테스트를 구성했습니다.

| 테스트 | 검증 조건 |
| --- | --- |
| `EmbeddingProviderTest` | 제공자별 호출, 컬렉션 선택, 빈 임베딩 예외 |
| `OllamaRagIntegrationTest` | 기대 근거가 검색 결과에 있는지, 타사 문서가 포함되는지, 출처가 존재하는지 |
| `ClaimServiceTest` | 중복·빈 주장, 잘못된 유형, 게시일 기준 상대 기간 처리 |
| `OllamaAnalyzeIntegrationTest` | 실제 대화·임베딩 모델 및 ChromaDB 호출, 검증 결과와 개인화 리포트 생성 |

통합 테스트는 2026년 1월 8일 게시 영상(`48WVf1ijerc`)과 가상 사용자 `demo_user_01`을 입력하여 HTTP 200 응답, 주장 3건, 공시 기간 및 출처, LLM 판정 상태, 개인화 설명을 검사하도록 구성했습니다. `MockitoSpyBean`으로 실제 메서드를 호출하면서 단계별 요청·응답과 검색 결과를 기록하고, JSON 리포트에 남기도록 구현했습니다.

- [공시 검색 통합 테스트](https://github.com/won-attack/won-attack/blob/e382d472d361243bc4285c8911b8948000040b27/backend/won-check-backend/src/test/java/com/woncheck/woncheckbackend/service/OllamaRagIntegrationTest.java) — 기대 문서 ID 및 기업 검증 조건 확인
- [전체 분석 통합 테스트](https://github.com/won-attack/won-attack/blob/48adb90ed11280dcd40d79c93c07a62a3d1603af/backend/won-check-backend/src/test/java/com/woncheck/woncheckbackend/api/OllamaAnalyzeIntegrationTest.java) — 실제 AI 호출과 검색 결과를 기록하고 응답을 검사하는 코드 확인

커밋에는 Ollama 테스트 완료가 기록되어 있습니다. 테스트 원본 실행 로그와 생성된 JSON 결과는 현재 제출 자료에 포함되어 있지 않아 개별 실행 결과 및 전체 사실 판정 정확도 수치는 기재하지 않았습니다.

## 5. 구현 결과 및 현재 범위

등록된 대본에 대해 투자 주장을 추출하고, 공시 근거를 검색해 `SUPPORTED`, `CONTRADICTED`, `INSUFFICIENT_EVIDENCE`, `PREDICTION`으로 판정하는 로컬 PoC를 팀으로 완성했습니다. 검색된 공시 원문 링크와 사용자별 위험 설명도 제공하는 흐름을 구성했습니다.

팀 문서에는 OpenAI 임베딩을 사용한 시연 주장 7건의 검색 점검 결과, 기대 공시가 7건 모두 Top 3에 포함되었고 다른 기업 문서가 섞인 사례가 0건이라고 기록되어 있습니다. 이 수치는 제한된 시연 데이터의 **팀 검색 테스트 기록**입니다. [데이터 검색 점검 기록](https://github.com/won-attack/won-attack/blob/0a330b6ac704274acc21eb2384472cc45be4ac48/data/README.md)

## 6. 협업 경험과 배운 점

공시 검색 기능을 개발하던 중 DB 담당 팀원이 데이터 적재 및 검색 코드를 먼저 작성하여 일부 개발 범위가 중복되었습니다. 구현된 코드를 반복해서 작성하면 제한된 개발 시간을 낭비한다고 판단해 중복 작업을 중단하고 기존 코드를 활용하는 방향으로 조정했습니다. 팀원에게 담당 범위가 겹치는 기능은 구현 전에 공유하자고 제안했고, 이후 Backend-A와 Backend-B를 통합하여 검색 및 사실 검증 연동을 이어갔습니다. [27fa524 — 백엔드 코드 통합](https://github.com/won-attack/won-attack/commit/27fa524317d5c9181a08ef2550e1ff591e54cbe2)

이를 통해 서비스 간 인터페이스와 담당 범위뿐 아니라 작업 진행 상황을 공유하는 시점이 중요하다는 점을 배웠습니다. AI 기능에서도 검색에 사용되는 기업·기간과 주장 유형의 정확성이 최종 검증 결과에 영향을 준다는 점을 확인하고, 추출 결과의 검증과 통합 테스트를 구성했습니다.

## 7. 한계와 개선 계획

| 현재 한계 및 영향 | 다음 개선 작업 | 완료 확인 조건 |
| --- | --- | --- |
| 등록된 대본과 사전 적재 공시 범위 내에서 분석 가능 | 신규 영상 전사 및 최신 공시 적재 과정을 분석 요청과 연계 | 미등록 영상을 분석할 때 필요한 데이터를 확보하거나 실패 원인을 반환 |
| 영상 게시일 기준 상대 기간 정규화는 구현했지만 공시 발표일 제한은 미구현. 게시 이후 공개된 공시가 검색될 수 있음 | 공시 발표일 메타데이터를 활용하여 분석 기준 시점 이전 문서만 조회하는 검색 옵션 구현 | 영상 게시 이전·이후 공시를 준비한 테스트에서 기준 시점 이후 근거 제외 확인 |
| 기간 필터 결과가 없으면 기업만으로 재검색. 다른 분기 결과가 판정에 영향을 줄 수 있음 | 기간 불일치 근거의 처리 기준을 명시하고 해당 분기 근거가 없으면 근거 부족으로 판정하도록 검증 강화 | 다른 분기 공시만 있는 테스트에서 사실 확인 판정이 발생하지 않음 |
| 검색 유사도 임계값과 재무 수치의 독립 검증 미구현. 관련성이 낮은 문서나 LLM의 수치 판단 오류 가능 | 단위·기간·재무 항목의 일치 검사와 검색 관련성 기준 추가 | 수치 단위 및 기간이 다른 공시를 넣은 테스트에서 부적절한 근거로 판정하는지 확인 |

실서비스 배포와 실계좌 연동은 구현 범위에 포함되지 않았습니다. 현재 서비스는 가상 사용자 데이터와 로컬 실행 환경을 사용합니다.
